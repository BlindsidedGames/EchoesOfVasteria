# Independent tile naming consumer audit

Reviewed current AllPacks/tiles.json (4,800 sprites), C# under Assets including Editor and BetterRuleTiles, and historical output/scene-review tools. Read-only; no Unity control.

- HabitatAnimal.cs:51–52 uses Grass_ and Water_Middle prefix predicates. Every proposed sprite preserves both old predicates; checked across all 4,800 records.
- MatchLoggingLayer.cs parses `int.Parse(t.name.Split('_').Last())`. Its -2 Old Path input currently contains FarmLand_Wet_Tile_N assets that will lose numeric suffixes. Replace parsing with original-index lookup using asset GUID/local ID in the frozen mapping, or retire this historic layout-copy tool explicitly. Mapping target lookup already uses GUID and remains safe. Its old layout algorithm was independently diagnosed as flawed; adapting lookup does not make it suitable for the new contour fix.
- RemoveMineRails.cs checks exact Stone_Cliff_3_Cave_Entrance sprite names twice and loads Stone_Cliff_3_Cave_Entrance_No_Rails.png by exact path. Adapt to LightGreenCliff_TimberCaveEntrance_WithRails_Assembly and the mapped WithoutRails source path, preferably GUID lookup. This is historic destructive editor tooling: compile/dry-run only, do not execute during naming migration.
- DressValley.cs and ValleySecondPass.cs dynamically form Outdoor_Decor_83/84/126/127. These are absent from the rename mapping and must remain unchanged. SimplifyRestAreas uses Outdoor_Decor_84 and Tent_Small_0/Camp_Decor_1/Picnic_Basket_0/Benches_1/Picnic_ predicates: these too are absent from aliases and should remain unchanged.
- Historical tools dynamically construct AnimatedDecor prefab paths (Grass_1_Anim etc, Rock_{variant}_Anim.prefab). Sprite/Tile renaming does not authorize prefab filename or GameObject renames. Preserve these paths and names.
- SetupHabitatAnimals.cs uses animal rect ordering, animation reference ordering and Butterfly_N lookups; animals are outside current tilemap mapping. Preserve unchanged. Its Grass_LightGreen_Fill lookup is already migrated and remains valid.
- ToolkitBookMigration.cs genuinely calls Sprite("UI_Buttons", "5"), but that source is UI rather than a renamed tilemap sheet. Preserve this context-qualified numeric lookup. Never globally replace aliases such as 1/5/6; same names exist on unrelated sheets.
- BetterRuleTiles SpriteReplaceWindow.cs:343–350 dynamically replaces substrings of sprite names and searches matching names. This is a user-driven editor operation, not a hard-coded consumer requiring source edits. Semantic palette naming will change which search/replace patterns users should enter; document GUID/mapping selection rather than assuming legacy numeric conventions. SpriteCache sorts names for picker display; TilesetData sorts authored sprite layout by rect.y/rect.x, so naming does not reorder tile assembly.
- DecorConfig.cs copies tile.name into display Name. Existing cached DecorEntry labels should follow mapped names only; preserve references, densities and generation behavior. BetterRuleTileGenerator assigns templateTile.Name to generated tile.name; retain rule container names/rules unless separately reviewed, or regeneration may restore authored labels. This does not break sprite references.

Exact source-path audit of all ten planned spriteMode-1 moves found one C# path consumer: RemoveMineRails.cs above. No TileGrass_ dynamic C# consumer found. Diagnostic logs that merely display sprite/tile names need no behavior change.
