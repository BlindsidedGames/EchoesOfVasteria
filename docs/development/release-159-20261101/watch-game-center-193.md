# Watch Game Center signing correction, iOS 193

The user authorized correcting the Watch entitlement after public builds 191 and 192 both failed Add for Review with `STATE_ERROR.BUILD_INDICATES_GAME_CENTER_DISABLED`. The phone's Game Center key was already true in signed XML, DER, and its embedded provisioning profile. Approved build 186 has the same phone requirements and GameKit linkage; it contains neither the Watch app nor widget.

`LiveActivityIosPostprocess.ConfigureCompanion` now preserves any existing generated Watch entitlements, explicitly sets `com.apple.developer.game-center = true`, configures that file for every Watch build configuration, and adds the Game Center capability. GameKit is linked directly to the Watch target because Unity's capability helper routes its framework links to UnityFramework. The modern Watch app is a single executable target; there is no separate WatchKit extension. The WidgetKit extension is unchanged. No Watch Game Center UI or gameplay feature is added.

The iOS build number is 193, reserved after the coordinator's fresh App Store Connect inventory showed 192 as the highest upload, including processing uploads. Marketing version remains 1.5.9 and Android remains 187. Approved player notes are unchanged.

The postprocessor compiled against the installed Unity Xcode assembly, and its actual companion configuration method ran against an APFS clone of the verified 192 native export. The verification driver substitutes Unity editor settings and retains the already verified character portrait catalogs; it does not constitute a fresh Unity build. All four generated Watch configurations point to the entitlement file and Watch directly links GameKit. Phone signing and widget settings remain unchanged. An exhaustive native export file comparison found exactly five changed inputs: the three bundle Info.plists (only CFBundleVersion), the Xcode project, and the new Watch entitlement file. All Unity data, generated C++, Swift/Objective-C source, and artwork are byte identical to 192. Ignored evidence is retained under `Artifacts/PublicRelease15920261101-193`.

Archive, provisioning, signed-package checks, and upload are pending. The archive must use normal automatic provisioning updates for the affected Watch App ID/profile; do not delete unrelated profiles. Before upload, verify the Watch key in signed XML and DER and the embedded profile, preserve the phone key, ensure the widget still omits it, compare gameplay data/native instructions to 192, and verify the reviewed source is pushed on main. Upload acceptance is separate from processing and successful Add for Review.

The Watch classification explanation is a supported hypothesis until a corrected build passes submission. A [firsthand report](https://stackoverflow.com/a/77025003) describes the same error with a non-Game-Center Watch companion and successful submission after enabling its capability. Apple's [watchOS capability reference](https://developer.apple.com/help/account/reference/supported-capabilities-watchos/) lists Game Center. The report uses the older WatchKit app/extension layout, so this change applies the entitlement to the modern Watch app executable instead.
