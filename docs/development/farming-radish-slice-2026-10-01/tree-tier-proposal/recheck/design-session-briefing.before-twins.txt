# Facts for the collaborative farming design session

Read-only briefing, 1 October 2026. Further farming UI/mechanics work is paused. Existing work remains uncommitted and preserved. A seed grid, per-crop growing levels, three waterings, eventual auto-water, growing XP and level-based growth speed are **discussion ideas**, not approved mechanics or balance.

## What exists now

**Adventure Farming:** the hero waters spawned crop tasks during an adventure. `FarmingTask` shows wet soil on arrival, progresses through an initial sprite plus three changes at task-duration quarters, and hides the crop/wet overlay on completion. Interruption hides the wet overlay. The visual stage sequence is continuous task work, not three separately paid watering visits. It uses skill/buff task-speed multipliers and the hero's Water animation. The Radish prefab binds an authored 16×16 wet-soil tile, so useful existing art exists; the permanent field needs coherent edge/corner coverage rather than placing one isolated wet square everywhere.

Adventure task completion grants Farming XP and ordinary crops through `BaseTask`/`ContinuousTask`. Authored base XP runs from Radish 3 to Turnip 50; all 17 crop pools show an authored 1–5 primary crop range. These are input values, not measured per-return earnings. Skill/buff XP bonuses, DoubleXP and Echo performer scaling (25% before the ordinary XP bonus path) can alter awarded XP. Existing adventure Echo effects are distinct from town Alter Echo resource generation.

**Isolated town-farm prototype:** only the two original beds and Radish are implemented in the development scene. A pack starts one finite batch; elapsed time grows it online/offline; a ready harvest empties the batch. Current development tuning is 30 minutes and 10 base Radish, not release tuning. Four Radish presentation sprites are selected at thirds plus ready. No watering state/action, per-crop XP/mastery or farm-harvest Farming XP is present. A `DurationSeconds` value is captured when planting, rather than continually consulting current skill level. Production Main has no farm service. Do not describe the prototype as an agreed full design.

**Existing Farming skill:** `Assets/Scriptables/Skills/Farming.asset` uses `10 × level^1.5` XP for the next level. This is a power curve, not multiplication by 1.5 on each level. SkillController carries excess XP across levels and saves Level/CurrentXP. Required XP is 10 at level 1, about 316 at 10, 3,536 at 50 and 10,000 at 100. Adventure task speed is `1 + 0.01 × Farming level` (before separate buffs), so level 50 has a 1.5 multiplier. That formula currently does not accelerate elapsed town-farm growth.

| Authored Farming milestone | Current effect and progression |
| --- | --- |
| Bonus Farming Resources | Starts level 5, increases every 5; passive 2.5% per tier, active 5% per tier. Its referenced effect changes adventure resource drops. |
| Bonus Looting XP | Starts level 10, increases every 10; passive 10% per tier, active 25% per tier. This improves **Looting** XP, not Farming XP. |
| Echo Farming | Infinite mode starts level 25, increases every 10: 0.5% initial spawn chance, +0.25 percentage points per tier. Passive references a Farming-capable Echo; active references a general Task Echo. The serialized manual level-1/200 tier list is inactive under this mode. |
| Tasting Turmoil | Manual tiers 50/200/400: passive magnitudes 1/1/2, active 2/3/5. Existing effect adds stew per taste and a `1 + magnitude` card multiplier. |

These are current source facts, not a proposal to retain or replace every perk. No authored auto-watering milestone/effect was found among Farming's four referenced milestones. A separately authored Double Farming Resources effect exists but is not in that Farming milestone list; its mere presence is not an unlocked Farming perk.

## Crop access and art

Current adventure crop levels: **Radish 1; Corn 7; Wheat 13; Watermelone 18; Carrot 23; Spud 29; Tomato 35; Lettuce 40; Cucumber 45; Leek 52; Parsnip 57; Pepper 62; Chillie 68; Pumking 74; Strawberry 79; Funion 84; Turnip 90.** These names are actual stable asset/resource keys, including spellings. TaskWeightService checks current skill against authored TaskData requirements. The old “Unlock crop” collection quests charge crop resources and award XP; names alone do not prove adventure task prerequisites.

Prepared art has 22 known packets plus a shared unknown, while gameplay has 17 crops. Mapping is not automatically one-to-one: current Radish prefab uses Eggplant-labelled plant art; Lettuce uses Cabbage; Pepper uses Beet; Turnip uses Radish; Parsnip uses a pale-root family; Funion uses a tan bulb. Cucumber's existing prefab array is rotated relative to its semantic growth ordering. A three-growth-stage design can reuse existing early/young/developed/mature art, but which states are visible and when the three waterings occur needs agreement. Art availability does not settle mechanics. [Exact current references](../../planning/farming-expansion-2026-09-30/crop-asset-inventory.json) retain the observed bindings; no remapping was done.

Seed packets are fresh discoveries for everyone. Retained old skill Level/XP can meet current game-defined requirements but cannot reveal/grant a pack or imply existing per-crop mastery. Old crop access is not grandfathered; meaningful quest progress remains a separate migration responsibility. No compensation or starter-gear conversion is approved. The approved seed direction is plant pools and 10% behind a farming quest; exact quest, matching/global pool behavior and adventure Echo eligibility still need definition. Three waterings, growth XP and mastery would revise earlier provisional no-watering/no-harvest-XP recommendations; those earlier recommendations are not decisions.

## Existing UI conventions to choose between

- **Inventory:** actual ToolkitGrid, up to six columns and fewer at narrow widths, point-filtered icons with quantity, selection outline, selected-item heading and vertical scroll. Unknown resources use the authored UnknownIcon and “Undiscovered”/“???”. Prepared seed unknown art already follows this approach.
- **Cauldron collections:** grouped flex card grids, resource/buff/eternal tabs, name/count, tier colors and progress strip, with tooltips. Crop-specific mastery could be displayed in a related card structure, but its color/tier language must not silently become Cauldron rarity.
- **Statistics Items:** detailed one/two-column rows, sorted known/unknown, counts and collected/spent totals. Undiscovered items withhold icon/name. It is not the same six-column component as inventory.

A seed grid is feasible using actual reusable components, but “like stats/inventory/cauldron” permits different density and selection/detail behavior. Agree whether the grid is an inventory, planting selector or mastery collection, then whether a selected crop drives bed actions. Quantity, discovery, access requirement and mastery should stay distinct. Existing TownCameraPan/View bed and a readable bed list remain available context, particularly for low vision; no new layout was authored in this pause.

## Integration choices that need design agreement

1. **Watering contract:** does a missed watering stop growth, only reduce a bonus, or delay a stage? Are there three player actions per batch, and can all be queued? Does offline growth stop at the next unwatered stage? Auto-water must specify whether it supplies actions, changes elapsed-time settlement, or removes a step. These produce materially different return habits and offline behavior.
2. **Progression ownership:** global Farming XP from town growing would also accelerate the existing adventure crop gates, adventure resource perks, Echo chances and Tasting Turmoil. Crop-specific mastery is a separate proposed progression, with no current saved farm field. Reusing adventure task completion counts would mix growing with old adventure history and contradict “levels from growing” unless explicitly chosen.
3. **When XP is earned:** planting, each watering, a completed growth stage, readiness or harvest each needs an exactly-once durable identity. Harvest-only has an existing commit boundary; unattended readiness requires settlement to capture newly earned XP even when no harvest occurs. Applying SkillController.AddExperience after save publication alone risks duplicate/lost rewards on recovery; the immutable snapshot must include the skill contributor state and any mastery state before notification. No option has been implemented.
4. **Speed and reward contract:** determine whether a planted batch freezes its speed/XP/yield terms or resettles with changing skill/mastery/perks. A farm-specific rule should not blindly inherit adventure task-speed buffs or resource/DoubleXP events. Harvest must not recursively count as adventure work, seed drops or BestPerMinute. Whether retained skill makes veteran farms faster from the first batch is a design choice, not compensation.
5. **Mastery scope:** a saved per-crop earned-XP/harvest-work value can derive its level from game-defined thresholds, avoiding redundant unlocked/level caches. One global skill only avoids a second progression but cannot express crop-specific improvement. Any alternative must define fresh starting values, cap/benefit and whether all planted visual copies count as one bed batch. These are integration options, not recommendations adopted as decisions.
